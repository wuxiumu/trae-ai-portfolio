# 03 · 技术架构

## 框架选择

**Astro 5** — 零 JS 静态站，`output: 'static'` 构建后纯 HTML/CSS/JS 产物，扔到任何 CDN/Pages 即可。

## 目录结构

```
game-wuqingbao-com/
├── doc/                     # 项目文档（编号文件）
├── games-list.md            # 游戏主清单（clone 脚本输入）
├── site/                    # Astro 项目
│   ├── src/
│   │   ├── data/
│   │   │   ├── taxonomy.js  # 9 大分类 + 标签词表
│   │   │   └── loader.js    # import.meta.glob 聚合所有 game JSON
│   │   ├── games/           # ★ 每游戏一份 JSON（schema 2）
│   │   ├── i18n/index.js    # UI 字典
│   │   ├── lib/nav.js       # URL 与语种切换 helper
│   │   ├── layouts/Base.astro

│   ├── public/
│   │   ├── styles.css
│   │   └── vendor/          # ★ 游戏原始静态文件（iframe 从这里加载）
│   ├── seeds.json           # 待抓取种子清单（完整元数据）
```

## 数据流

```
games-list.md ─────────┐
                        ├─→ clone-all.sh ──→ vendors/<slug>/
site/seeds.json ────────┘
                        │
                        ▼
                 fetch-games.mjs
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
  public/vendor/<slug>/  src/games/<slug>.json  logs/*.jsonl
            │                    │
            ▼                    ▼
     iframe 加载          loader.js 聚合
                                 │
                                 ▼
                      Astro 页面渲染 → dist/
```

## 关键设计

### vendor 路径（不是 public/games）

游戏静态文件放 `public/vendor/<slug>/`。原因：Astro 路由 `/games/[slug].astro` 会生成 `dist/games/<slug>/index.html`（详情页），如果游戏文件也放 `public/games/`，两者路径冲突互相覆盖。

### 每游戏一份 JSON

`src/games/<slug>.json` 由脚本自动写入。好处：

- 加游戏不改已有文件，零冲突
- `import.meta.glob` 自动发现新文件
- 可以 git 追踪单款游戏的变更历史

### 三种可玩状态

| 状态 | 条件 | 详情页表现 |
|---|---|---|
| 本地可玩 | `fetched: true` + `entry` 有值 | iframe 嵌入 |
| 外链试玩 | `fetched: false` + `play` URL 存在 | "在线试玩 ↗" 按钮 |
| 即将上线 | 两者都无 | "Coming Soon" + 源码链接 |
